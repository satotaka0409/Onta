# 8. ストリーム画面の使い方

この章では、ストリーム画面を使って音楽をカセットテープへ「ストリーム録音」し、テープから「ストリーム再生」する手順を説明します。
各表示項目の意味は、[4. ストリーム画面の説明](./04_ストリーム画面の説明.md) を参照してください。

## 8.1 ストリーム機能とは

ストリーム機能は、音楽を Opus で圧縮したデジタルデータを OFDM でカセットテープへ連続記録するモードです。

- ファイル送受信（ファイル画面）との違い
  - ファイル画面: 1 つのファイルをブロック単位で送り、受信側で元のファイルを復元する
  - ストリーム画面: 音声を途切れなく流し続ける。**曲の途中から再生しても再生できる**
- 音声と一緒に「曲タイトル」「アーティスト」「ジャケ写」も記録します。再生するとこれらが画面に表示されます。
- チャネルは**ステレオ専用**です（L/R に別々のデータを載せます）。
- 誤り訂正は畳み込み符号のみです（RS・ターボ符号は使いません）。

## 8.2 画面の構成

ストリーム画面は、上段が「送信（録音）」、下段が「受信（再生）」です。

### 8.2.1 送信（録音）

| 項目 | 内容 |
| :--- | :--- |
| 速度 | 記録速度（Opus のビットレート）。18 / 20 / 23 / 24 / 28 / 30 Kbps から選ぶ |
| 入出力 | 入力元（ファイル入力 / 音声入力）と出力デバイス・音量 |
| 入力ファイル | ファイル入力時の音声ファイル（WAV / FLAC / MP3）。表示欄へのドラッグ＆ドロップも可 |
| 入力デバイス | 音声入力時の録音デバイスと音量 |
| 出力デバイス | カセットデッキへつなぐ音声出力デバイスと音量 |
| 曲タイトル / アーティスト | 記録する曲情報（任意） |
| ジャケ写 | 記録する画像ファイル（PNG / JPEG / BMP）と画像形式 |
| バイト数 / サイズオーバー | 変換後のジャケ写のバイト数。4096 バイトを超えると「サイズオーバー」 |
| スタート / ストップ | 録音（送出）の開始と停止 |

### 8.2.2 受信（再生）

| 項目 | 内容 |
| :--- | :--- |
| 速度 | 受信中のストリームから自動検出した速度 |
| 入力デバイス / 音量 | カセットデッキの出力をつなぐ録音デバイスと音量 |
| 出力デバイス / 音量 | 受信した音声を再生するデバイスと音量（受信中も変更可） |
| 曲タイトル / アーティスト | 受信した曲情報 |
| ジャケ写 | 受信した画像とそのサイズ・バイト数 |
| スタート / ストップ | 受信の開始と停止 |

### 8.2.3 グラフ

画面下部には次のグラフが表示されます。

- エラーレート / FFT（ラジオボタンで切り替え）
  - エラーレート: 受信中の誤り訂正（ビタビ）の訂正率（受信時のみ）
  - FFT: L（緑）/ R（オレンジ）のスペクトル（Hanning 窓）
- I-Q: 変調点の分布（サブキャリアグループ A〜H ごとに色分け）

受信中は**受信している信号**、送信中は**送出している信号**が表示されます。

## 8.3 速度の選び方

速度が速いほど音質は上がりますが、テープの状態に対して厳しくなります（変調が多値になり、高い周波数のサブキャリアまで使うため）。

| 画面表示 | 変調 | Opus ビットレート | 目安 |
| :--- | :--- | :--- | :--- |
| 18Kbps | 48SC / 8PSK | 18.4 kbps | 最も安定。テープ状態が悪いとき |
| 20Kbps | 56SC / 8PSK | 20.4 kbps | |
| 23Kbps | 64SC / 8PSK | 23.2 kbps | |
| 24Kbps | 48SC / 16QAM | 24.8 kbps | |
| 28Kbps | 56SC / 16QAM | 28.4 kbps | |
| 30Kbps | 64SC / 16QAM | 30.4 kbps | 最も高音質。テープ・デッキの状態が良いとき |

- どの速度でも、1 パケットの送出時間は運ぶ音声より数 % 短く設計されています。余った時間はパケットの間に無音を入れて埋め、曲の再生速度どおりに送り出します。録音時間は曲の長さとほぼ同じです。
- 迷ったら 18Kbps で録音・再生できることを確認し、そこから段階的に上げてください。
- 高域（10kHz 以上）が落ちるデッキやテープでは、56SC / 64SC（20 / 23 / 28 / 30Kbps）が不安定になりやすいです。性能測定画面の FFT や I-Q で事前に確認すると確実です（[9. 性能測定画面の使い方](./09_性能測定画面の使い方.md) 参照）。

## 8.4 手順1: 録音の準備

### 8.4.1 配線

1. PC の音声出力をカセットデッキの LINE 入力へつなぎます。
2. 再生も行う場合は、カセットデッキの LINE 出力を PC の音声入力へつなぎます。
3. デッキの録音レベルは、最初は控えめに設定します。

### 8.4.2 入力元を選ぶ

- ファイル入力
  1. 「ファイル入力」を選びます。
  2. 入力ファイルの「...」ボタンで音声ファイル（WAV / FLAC / MP3）を選びます。表示欄へドラッグ＆ドロップしても同じです。それ以外の形式はドロップできません。
- 音声入力
  1. 「音声入力」を選びます。
  2. 入力デバイス（例: ライン入力、ステレオミキサー）と音量を設定します。
  3. 音声入力の場合、ストップを押すまで録音が続きます。

### 8.4.3 出力デバイスを選ぶ

1. 出力デバイスで、カセットデッキへつないだデバイスを選びます。再生は、そのデバイスのサンプリング周波数で行われます。ストリームの信号は 44100 Hz で、違うときは変換して出します。
2. 音量スライダーで出力レベルを調整します。
   - 大きすぎるとデッキ側で歪み、I-Q が崩れる原因になります。
   - 小さすぎるとノイズに埋もれます。

## 8.5 手順2: 曲情報とジャケ写を設定する

曲情報はすべて任意です。**入力しなかった項目は記録されません**（その分、入力した項目が早く伝わります）。

### 8.5.1 曲タイトル / アーティスト

- それぞれ最大 256 文字まで入力できます。

### 8.5.2 ジャケ写

1. 「ファイル指定」で画像ファイル（PNG / JPEG / BMP）を選びます。
2. 画像形式を選びます。画像は選んだサイズに縮小され、PNG に変換されます。

| 画像形式 | 解像度 | 色 |
| :--- | :--- | :--- |
| 32x32カラー | 32 × 32 | カラー |
| 48x48カラー | 48 × 48 | カラー |
| 48x48白黒 | 48 × 48 | グレースケール |
| 64x64白黒 | 64 × 64 | グレースケール |

3. 変換後の「バイト数」を確認します。
   - 上限は 4096 バイトです。超えると「サイズオーバー」と表示され、スタートできません。
   - サイズオーバーの場合は、小さい形式や白黒を選んでください。

### 8.5.3 ジャケ写の転送にかかる時間

曲情報は、パケット 1 個につき 16 バイトずつ、タイトル → アーティスト → ジャケ写の順に交互に送られます。ジャケ写が大きいと、受信側で全体がそろうまで時間がかかります。

| ジャケ写のサイズ | 18Kbps | 30Kbps |
| :--- | :--- | :--- |
| 1024 バイト | 約 75 秒 | 約 47 秒 |
| 4096 バイト | 約 5 分 | 約 3 分 |

（タイトル・アーティスト・ジャケ写の 3 種類をすべて送る場合の目安）

- 短い曲では、ジャケ写が最後まで届かないことがあります。**1024 バイト程度に収めるのがおすすめ**です。
- 曲情報は繰り返し送られるので、曲の途中から再生しても、しばらく待てば表示されます。

## 8.6 手順3: 録音する

1. 速度、入力元、出力デバイス、曲情報を設定します。
2. カセットデッキを録音状態にします。
3. 送信の「スタート」を押します。
   - 送信中は、ストップ以外の送信側の設定は操作できません。
   - 送信中は受信を開始できません（送信と受信は同時に実行できません）。
4. FFT と I-Q で送出している信号を確認します。
   - FFT: 約 550Hz〜サブキャリア上限まで、L/R とも信号が出ている
   - I-Q: 選んだ変調（8PSK / 16QAM）の点が表示されている
5. 録音を終えるときは、送信の「ストップ」を押します。ファイル入力の場合は、ファイルの最後まで送ると自動で終了します。
6. カセットデッキを停止します。

## 8.7 手順4: 再生する

1. カセットデッキの LINE 出力を PC の音声入力へつなぎます。
2. 受信の入力デバイスと音量、再生に使う出力デバイスと音量を設定します。
3. 受信の「スタート」を押します。
4. カセットデッキを再生します。曲の途中からでも構いません。
5. 受信が始まると、次のように表示されます。
   - 速度: 録音時の速度を自動で検出して表示
   - 曲タイトル / アーティスト / ジャケ写: 各項目のデータがすべてそろった時点で表示
   - ジャケ写の取得率: そろうまでの進み具合（取得済みブロック数／総ブロック数）
   - ステータス: 「受信中… パケット n（エラー m）」と、受信できたパケット数と受信できなかったパケット数
6. グラフで受信状態を確認し、必要なら入力音量を調整します。
   - FFT: 約 550Hz〜サブキャリア上限まで、L/R とも信号が入っている
   - I-Q: 点が理想位置の周りに小さくまとまっている
   - エラーレート: 低いほど余裕がある。上がってきたら音量やデッキの状態を見直す
7. 終わるときは、受信の「ストップ」を押します。

補足:

- 別のストリーム（別の録音）に切り替わると、表示中の曲情報はいったん消え、新しいストリームの曲情報を最初から取り込み直します。
- 曲情報にエラーがあった部分は捨てられ、次に同じ部分が送られてきたときに取り込まれます。
- 入力デバイスは、そのデバイスのサンプリング周波数（48000 Hz など）で録音します。取り込んだ音は 44100 Hz に変換してから受信するため、送信側の PC とデバイスのサンプリング周波数が違っていても受信できます。

> **現在のバージョンの制限**
> 受信した音声の WAV 出力は未実装です。再生は出力デバイス（LINE 出力）のみです。

## 8.8 よくある問題と対処

- スタートが押せない
  - ジャケ写が「サイズオーバー」になっていないか確認する
  - もう一方（送信 / 受信）が実行中でないか確認する
- スタート直後に「失敗: 入力ファイルがありません。」と表示される
  - ファイル入力で入力ファイルを選んでいるか、ファイルが移動・削除されていないか確認する
- 受信しても速度や曲情報が表示されない
  - 入力デバイスと配線を確認する
  - 入力音量を上げる / 下げる（小さすぎても大きすぎても受信できません）
  - 速度は録音時の設定を自動検出するので、受信側で速度を合わせる必要はありません
- 速度は表示されるが、曲情報がなかなかそろわない
  - 録音時の速度を下げる（例: 30Kbps → 24Kbps → 18Kbps）
  - デッキの録音レベル、PC の出力音量を見直す
  - デッキのアジマスを調整する（性能測定画面のリサージュを使用）
- 受信エラーが多い、ステータスの「速度」の値が大きい
  - ステータスの「速度」は、録音時と比べた再生速度のずれ（推定値）です。±4% 程度までは自動で補正します
  - 値が大きく揺れ続ける場合は、テープの走行（ワウフラッター）が不安定です。デッキのキャプスタン・ピンチローラーの清掃や、別のデッキでの再生を試してください
- ジャケ写がなかなか表示されない
  - ジャケ写のバイト数を小さくして録音し直す（1024 バイト程度推奨）
  - 使わない曲情報（タイトル・アーティスト）を空欄にすると、ジャケ写に回る分が増える

## 8.9 最短の実施パターン（迷ったとき）

1. 18Kbps、ファイル入力で短い曲を録音する（曲タイトルだけ入力）
2. テープを再生し、速度と曲タイトルが表示されることを確認する
3. 曲タイトルがすぐに表示されるようなら、24Kbps → 30Kbps と上げて録音し直す
4. 安定していた速度で本番の録音をする（ジャケ写は 1024 バイト程度に抑える）
